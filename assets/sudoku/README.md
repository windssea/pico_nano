# PicoNano 数独界面与题库 · 设计交付 v1

这是设备原生素材、静态界面设计和主机出题工具。已接入同源可玩数独与内部A/B续局，紧凑题库只读链接；PNG仍仅为v1设计参考，游戏使用像素图元和静态熊猫，周期动画已移除。2026-10-25题库采用入门分级v2；旧设计稿的中等例题保留在`screen_puzzle.json`，已退出当前产品题库。题库分级是 PicoNano 内部规则，不等于其他软件的难度分数，仍需玩家试玩标定。主机验证不代表面板残影、触控、功耗或断电恢复已通过。

## 原生像素与16阶

- 屏幕固定684×1216。棋盘左上角(36,216)，宽高612，每格68。三宫分割3px，普通线1px。
- 文字、棋盘、按钮由绘制层动态生成；PNG稿用于对照。不能用整张界面图替代可交互页面。
- 亮度严格为0、17、34……255，对应固件G0黑至G15白，无抖动。
- 不透明PNG使用固定16项调色板，PNG位深4；不是仅在RGB文件名中标注“16阶”。
- 熊猫PNG使用RGBA，RGB仍只含16阶，alpha仅0/255；白脸和白肚皮为不透明白，不会被透明化。PNG容器不是原始4bpp帧，接入时应读取RGB灰阶，并单独处理透明掩码。
- 熊猫逻辑画布48×48，整数最近邻放大为96×96和144×144，脚底基线固定，留有边缘空间。游戏页使用96，选择页中部使用144。
- 远山684×160，纯白纸底684×1216。纸底实际接入时直接填G15，不必存一张白图。
- `sources/`保留高分辨率生成原图，未量化；仅`assets/`与`screens/`是设备尺寸/灰阶候选成品。

## 三页行为

新游戏：简单、中等、困难、极难四个整行触控选项。选择只改变草稿；点“开始新游戏”才提交。存在未完成棋局时必须再确认，取消/返回不换题。首次进入与通关后选择难度不显示“当前未完成”文案，也无需放弃确认。

游戏中：先点格再点数字。初始数字用黑色粗字，玩家输入用G4常规字重；选中格用黑色内框，不能仅依赖灰色区分状态。笔记数字采用固定3×3位置，不将候选挤成一行。数字键192×64，横向间隔18，纵向间隔12。四个工具分别是撤销、擦除、笔记、菜单。菜单收纳提示、检查、重玩本题和新游戏。笔记启用时工具区需有边框和“笔记中”状态，不能只变灰。长按不是任何必需功能的唯一入口。

通关：保持同一尺寸和位置的完整棋盘，时间冻结，熊猫只庆祝一次。提供“同难度再来一局”“选择难度”“返回首页”；没有倒计时自动换题。再次进入恢复通关页，直到用户明确开下一局。

“重玩本题”清空本题输入、笔记、用时与撤销，保留题目身份，另行确认；“新游戏”更换题目。这两个操作不能合并为不明确的“重新开始”。

## 棋局生命周期与后续持久化契约

退出、锁屏、正常重启保留当前题目ID、题面、难度、玩家数字、候选位掩码、选中格、笔记模式、活跃用时、提示次数、完成标记以及有界撤销栈。进入选择页、校时、跨天、换TF、题库扩充都不自动换题。保存题面副本，避免题库更新/缺失使进行中的棋局不可恢复。

后续接入使用内部状态卷的版本化A/B或等价事务和完整校验；用户状态不存可回收缓存、不静默擦除NVS。显示“已保存”须等真实写入/读回成功；忙或失败时应显示“保存中”或“保存失败”，允许重试。应承诺恢复至最后可靠提交，不把尚未验证的每步突然断电都称为零丢失。普通退出、锁屏和新游戏替换前必须完成保存屏障；旧棋局不得在新题准备失败时先被销毁。

新游戏先准备并校验唯一解题目，再可靠提交新棋局，最后切换页面。通关后先提交完成状态；显示失败或存储失败不能自动生成另一题。新游戏可按本档未玩ID随机选，耗尽后再循环，避免紧邻重复；当前局独立于历史回收。

render只消费快照。输入、存储、时钟、题库选择、推屏属于控制层；不得为熊猫动画修改VCOM、波形或PMU时序。正式接入应让PC与设备共用逻辑核心，PC仅替换port。

## 动画

六个姿态：读书、眨眼、抬头、思考、举爪一、举爪二。`animation.json`给出进入、提示、通关的事件序列。默认不循环待机，不随选格或填数播放；有输入、推屏忙或低电时可直接保持静态帧。

约1000ms/帧只是设计占位节奏，需按本设备可靠GL16/GC16路径实测。控制层应等上一帧显示回执，不堆积动画帧；退出页面立即失效旧动画。`panda_motion.gif`为了便于在电脑查看而循环展示多种姿态，不是产品循环策略，不代表真实墨水屏流畅度。局部绘制也不是快速局刷能力证明。

## 四档逻辑题库

| 产品难度 | 主机标签 | 允许的最高技巧层 |
| --- | --- | --- |
| 简单 | easy / 0 | 44–50个已知数，仅裸单（直接排除） |
| 中等 | medium / 1 | 34–40个已知数，裸单、隐单（某数字在行列宫中只有一处可填） |
| 困难 | hard / 2 | 区块排除、裸数对、隐数对 |
| 极难 | expert / 3 | 增加裸三数组、X-Wing |

旧简单题只有23–36个已知数，虽然单数可解，找入口仍费力。v2简单档要求开局至少8个裸单，每行/列/宫至少3个已知数；按工具固定顺序逐格求解，在剩余空格不少于8个时每一步至少仍有3个裸单入口，整题只需31–37次填数。中等档开局至少2个裸单，每行/列/宫至少2个已知数，可逐步练习隐单。本次替换简单/中等各300题，困难/极难各300题原样保留。

`logical_solve`的`difficulty`仍表示旧四级技巧层；产品档位须调用`product_tier`，同时检查线索、入口和技巧，不能直接沿用技巧标签。固定顺序优先查找低层技巧，全部低层无进展才使用高层。全程不猜数；无法完成或不满足产品档位约束的题目拒绝入库。该策略不是穷举所有人类解法得到的最小难度，也不是玩家用时预测。独立精确覆盖验证唯一解，规则前提回放验证每步证明。

升级保留原局题面、填写、笔记、撤销与用时；新分级仅在明确开始新游戏后生效。PNSG schema2复用4个保留字节保存题库CRC归属，载荷仍764B，能读取schema1。下一局发现题库变化时只重置旧题库的已玩位图，不改当前棋局；题库CRC只用于历史归属，不能替代完整载荷校验或唯一解检查。

参考：[Radek Pelánek, Difficulty Rating of Sudoku Puzzles: An Overview and Evaluation](https://arxiv.org/abs/1403.7373)。本文用于解释分级方法的局限，没有复制论文题库或第三方商业题目，也不声称实现了论文模型。

出题流程：固定seed驱动随机完整终盘 → 随机挖空 → 每次挖空通过最多搜索两个解的位掩码求解器检查唯一性 → 逻辑求解并记录每一步规则前提 → 按最高技巧筛选 → 排除数字重命名与旋转/镜像重复 → 独立精确覆盖复验唯一解 → 导出。

当前去重覆盖八种平面旋转/镜像与数字重命名，不声称穷尽所有行带/列栈等价变换。随机完整终盘由搜索产生，不只是反复变换同一张固定终盘。来源为本项目工具生成，无外部题库内容许可证依赖。

## 题库占用与格式

1200题（每档300题）的候选设备文件为32字节头加1200×48字节记录，即57632字节，约56.28KiB。这个数字是题库文件大小，不能当作链接后镜像增量或设备总RAM实测。

每题：41字节题面（81个数字半字节打包，先高后低，0表示空格，末尾低半字节补0）、1字节难度、1字节已知数数量、1字节保留0、4字节小端稳定ID。完整答案与解题步骤只在主机JSON，不放入紧凑文件。设备按需读单题，不要求整库复制到RAM；解题/提示工作集另行计费。

32字节头按小端`<4sHHIIIIII`：魔数PNSD、schema1、记录长度48、题数、seed、题目载荷CRC32、三个保留0。ID来自规范化题面SHA256前32位，本批导出必须检查碰撞；不因扩库重新顺序编号。版本升级时必须完整核对题面，不能把32位ID当作内容完整性证明。

主机CSV/JSON含答案和完整步骤，体积较大，只用于审查和生成提示模型，不应整包编译进Flash。当前工具是Python离线算法，不是已在ESP32运行的出题器；将来移植时须使用同源C核心和有界可取消调度，禁止开局同步长时间占住UI。

## 复跑

需要Python与Pillow；字体只引用本机现有项目/系统字体，包内不复制字库。

```powershell
python sudoku_bank.py --per-tier 300 --seed 20261024 --workers 8
python build_design.py
python -m unittest discover -s . -p test_sudoku_bank.py
python verify_delivery.py
```

若扩至每档1000题，可把`--per-tier`改为1000。已有题库优先、检查点补充，全部按当前产品规则重新筛选并去重，不能把旧简单题直接带回。原样保留题的稳定ID不变；新增题目须重新完整验证。`bank/checkpoint.jsonl`为忽略的本机生成检查点，不是设备文件；删除它不影响已导出的题库。不同seed用独立目录，避免混合来源参数。精确批次来源见`bank/provenance.json`，不能把旧题保留加新题生成与全新单次运行混称逐字节可重现。

产品接入与软件证据见`docs/ARCHITECTURE.md`和`docs/DEVELOPMENT_PLAN.md`。本批已完成编译和模拟器验证，未刷机、未正式发布；原设计资源不代表面板验收。扩库工具可生成更大题库，但当前固件固定1200条及对应已玩位图，扩库须同步升级协议，不可仅替换二进制。
