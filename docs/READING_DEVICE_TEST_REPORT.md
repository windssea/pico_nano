## 方法与判定

1. 从首页最近阅读或书库选书，记录首个/末个显示回执；等显示静默12秒后查询`body=1`并保存原生起点帧。
2. 带等待：NEXT/PREV各3次，每次回执后保留1500ms静默，再比较往返正文/页脚。
3. 短间隔：NEXT最多15次，每次等显示回执但不额外留预热间隔（`quiet_ms=0`）；若8秒内无首回执，保存现场、查询状态，再无输入观察20秒。仅这次超时不足以判定持续卡页，还必须有后续PN_BUSY日志且观察期间无迟到显示。
4. 卡住时PREV恢复，再返回该书起点；未卡住的样本PREV15次返回。逐像素核对正文/页脚，排除顶部32行动态时间/电量。
5. 退出至首页后重开，核对`body=1`及起点数字帧。另对《白夜行》独立执行“退出→重开→立即连翻”，不先做3次演练。

短间隔测试仍是串行请求，不是同时按键，也未要求在每次扫描未完成时再次输入。等待超时不是吞掉失败的重试机制；失败请求、等待日志、恢复操作分别保存。首次开书的首回执可能是loading，故下表同时列出首/末回执，并以随后body与截图确认正文，不将loading耗时当开书完成。

## 风险与未验证项

真机最终仍为399cce7诊断镜像，保持本轮《绍宋》第8节起点供用户阅读，设置不变。最终串口`body=1`、`touch_errors=0`、`dropped=0`。这只能排除这些观测计数异常，不能排除所有输入问题。没有panic也不能排除任务不前进。

尚未定位持续PN_BUSY具体停在何层，缓存交接、预排、回执生命周期等仅为待检查路径。下一步应从失败请求保留的任务状态建立能失败的同源回归，再修根因；不得只靠延时、重启或超时强跳页宣称解决。本次仅测试/记录，没有生产代码修复或新刷镜像。

串口诊断、合成输入和现有缓存会影响时序。这里测的是输入至显示完成回执，不是人眼稳定、实体触控接触或功耗；未覆盖所有书/章节、无缓存首建整书索引、突然断电、USB并行或长期耐久。数字帧一致也不等于光学无残影。
