# 锁屏浅睡与自动锁屏

0.0.55把锁页接入浅睡（POWER-01的第一部分）。代码按参考固件在本板验证过的顺序移植，但本项目尚未烧写，浅睡电流、唤醒延迟与可靠性都未测；PMU软睡、关机、拿起唤醒和低电量处理仍未实现。

## 流程

1. 进入锁屏：电源键短按、传输停止后的锁屏，或无操作满5分钟的自动锁屏（开机后5分钟起算；传输中不触发，由传输自己的停止流程负责）。
2. 先执行原有保存屏障并关闭正文；保存失败不锁屏，留在原页提示。
3. 显示锁页（壁纸或系统默认，见 [锁屏与壁纸缓存](LOCK_SCREEN.md)），显示更新后显示轨照常关闭。
4. pn_device_sleep_until_key：等电源键松开且IOE中断线保持高电平150ms（最多800ms）；IOE_INT配置为输入上拉、低电平GPIO唤醒；循环中若入睡前中断线已为低，先排空PMU事件再判断，否则esp_light_sleep_start；醒来后只有read_pico_pmu_take_key_wakeup确认按键才退出，其他唤醒继续睡。
5. 退出时关闭GPIO唤醒，解锁并重新打开原书（没有原书时回书架），重新计时自动锁屏。

唤醒源配置失败时不浅睡，保持锁页并沿用主循环轮询电源键解锁。浅睡期间RAM、TF挂载与内部存储保持；不写PMU配置、不切EN、不访问TF。触摸三键与屏幕触摸不唤醒，只有电源键。

## 尚未实现

PMU软睡（锁屏后15分钟）与重启后自动续读、用户关机、拿起唤醒、自动锁屏时长设置、锁页静态电量/时间叠加、睡眠中卡拔出处理与功耗实测。

## 验证

两套ESP-IDF构建编译链接device_sleep与主循环；host的device_boot测试把浅睡函数设为断言陷阱，证明VCOM/NVS/挂载门等启动路径不会进入浅睡。没有可在主机上执行的浅睡模拟，必须真机测量。
