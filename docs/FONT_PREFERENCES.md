# 全局与逐书字体选择记录

PNFP持久层接入实际TXT/EPUB打开与阅读中的字体事务；[中文菜单](FONT_PICKER_UI.md)提供正文/备用选择、原文预览、逐书应用、全局默认及继承操作。替换/删除和上传仍需完成，不能称为完整字体管理功能。

## 选择与恢复

每份选择包含正文和可选备用两个引用：常驻子集或完整文件。文件引用保存规范绝对UTF-8路径、预期字节数和完整SHA-256，大小12字节至32MiB。仅支持POSIX绝对路径或正斜杠的Windows盘符绝对路径，拒绝相对路径、空段、点段、反斜杠、非法UTF-8和控制字符。文件名、字体名仍保留原文，内容身份不由路径或大小猜测。

逐书记录以原书内容SHA归属，可明确继承全局；继承记录的两个引用必须为空。全局不可继承。解析按“逐书明确选择 → 全局 → 调用方启动默认”顺序；逐书不存在或明确继承才读全局，两者都不存在才允许启动默认。损坏、未知版本/字段、身份错误或IO不走默认。明确逐书选择不读取未使用的全局字体，从而不受全局引用文件失效影响；全局异常记录仍保留。

常驻正文只是内置子集，不能承诺完整中文覆盖；常驻备用表示没有额外备用文件，回退链仍有常驻末级。字距/字号等仍在PNTS，不写进PNFP。

TXT/EPUB打开时先恢复选择，用已挂载源介质租约验证实际文件大小与完整SHA，再由真实字体引擎打开校验；备用也要核对并绑定独立只读源。已保存选择优先于打开参数中的启动字体。若字体缺失、同名替换成不同内容或校验失败，拒绝该次打开并保留配置、进度和字体文件，不默默删配置或切另一个文件。没有state目录仍只使用调用方参数。

引用身份检查是内容一致性检查，不是安全认证。owner排除字体并发修改；使用中的上传/替换/删除必须先停止消费者并关闭源，不能只依赖每个字形前的媒体租约验证。尚无自动坏记录修复和字体缺失的完整产品引导。

## 存储契约

root由内部存储owner提供且已存在，files辅助函数不新建目录或挂载。全局fonts.a/b，逐书SHA.fonts.a/b，各自使用PNBL双槽CRC、序号、同步读回，不改变PNTS/PNEP/TXT书签格式。

PNFP schema1最大2182字节。头部magic[0..3]、version16[4]、flags16[6]（bit0逐书，bit1继承）、book-SHA32[8]（全局必须全零）。两个48字节引用描述符从40、88开始：kind16[0]、path-length16[2]、size64[4]、font-SHA32[12]、reserved32[44]=0；136之后依次放两个路径，不带NUL。整数小端，未知版本/标志/kind/reserved拒绝。常驻引用的路径、大小和SHA必须为空。

保存先解析既有语义记录；损坏、未知schema或错归属不能直接覆盖。写错误可能已提交；界面owner需重读完整候选确认，再决定是否保留待提交请求。不要因为写入失败擦槽。删除字体不自动清选择，继承以显式记录表达，不删历史进度。

记录保存本身不改活动字体或画面。逐书应用与继承先校验候选、原文锚点重排及真实显示确认，再提交选择，失败保留草稿和旧源。更新全局保留已有逐书覆盖及当前接受组，之后打开生效；未设置全局时菜单继承提示先设置默认。字体事务分开保存运行组合与继承标记，关闭重试不会把继承错误转为文件覆盖。

## 验证

python tools/dev.py host：合法范围、全局/逐书/继承优先级、双槽各字节中断及已提交但返回IO、最大双路径、未知schema/reserved禁止读写、错书身份、同名改内容/缺文件/失效媒体与零保留分配。跨进程测试写入真实文件记录，另一进程恢复；改同名内容或移走文件后拒绝恢复且配置字节不变，恢复原文件后可读取。

实际TXT/EPUB测试把启动字体设为不存在路径，仍使用有效持久选择成功绘制，并检查原文位置；摘要错时拒绝打开，逐书明确选择可覆盖全局引用异常。其他分页、排版、书签、目录及保存屏障测试继续。

本机独立测试状态目录记录霞鹜文楷正文及完整Noto Sans SC备用，实际应用以不存在的启动字体打开《绍宋》成功并补齐测试页缺字；原锚点不变、pool峰1675754bytes后释放到0。字体、书籍与测试状态不随产品分发。软件测试不代替真机资源、刷新、掉电或体验验收。
