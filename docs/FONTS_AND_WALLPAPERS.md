# 字体上传与锁屏壁纸

状态：设计 v1.1，2026-10-05。用户明确新增字体上传与锁屏壁纸；字体上传从现有传书设计展开为独立管理流程，锁屏壁纸纳入0.1基础版本。当前字体加载/选择/偏好/上传已接，图片上传已接；锁屏壁纸预处理/内部记录/锁屏绘制内核已实现（见 [锁屏与壁纸缓存](LOCK_SCREEN.md)），完整字体管理与壁纸设置/应用流程尚未完成，当前状态见 [PROJECT_STATUS](PROJECT_STATUS.md)。

## 1. 字体上传：FONT-02

### 手机与电脑流程

传书网页提供“图书 / 字体 / 壁纸”三个标签。字体标签可批量选择TTF，显示文件名、容量、队列与校验结果；共享AP/STA、配对、覆盖确认及后续分块续传能力。成功后显示“字体已安装，停止传书后在设备选择”，不自动改变正在阅读的字体。

电脑还可在USB通过技术门后复制到 `/sdcard/fonts/`；退出USB后重扫并校验，未通过的文件标记不可用。手机网页初版不转换OTF/CFF/TTC/WOFF；明确提示当前接受TrueType轮廓的TTF。

单文件上限32MiB、总字体空间预检，不把整个文件装入RAM。显示字体内部家族名、样式、真实可变字重轴范围、内容摘要和中文/日文/拉丁抽样结果。覆盖抽样不代表覆盖整个Unicode；设备预览可展示缺失的样例字。附带许可证文件可由用户复制到字体旁；不假定用户上传字体授权允许再分发。

### 校验、安装和替换

先结构预检，再有界字形抽样与实际读取时边界检查，复用RENDERING预算与错误策略。扩展名正确但轮廓不兼容也必须失败；传输/校验失败保留旧字体。替换当前选中的字体前暂停阅读、保存位置、关闭字体源；传书期间UI用常驻字体，完成后只有用户确认应用才重排正文。

目录内容由字体索引记录，使用font内容摘要识别更新。相同名字的新内容不命中旧字形/页表缓存；同内容重复上传提示已安装。没有TF时提示“字体需要TF卡”，不悄悄塞进有限内部书库，也不隐藏字体上传标签。

### 设备管理

设置 → 显示与字体 → 字体管理：列表、样例预览、选择为全局默认、查看可变轴与缺字、删除。阅读 → 排版 → 字体：可选择逐书覆盖或“跟随全局”。更换字体定位原文锚点，PDF原版字体不被设备正文字体替换。

删除非使用字体先确认；使用中的字体先选择有效替代或确认回退，再关闭源和删除。若没有完整替代字体，提示可能出现正文缺字；UI始终可读。系统UI字体不能通过普通网页替换或删除。TF拔出保持保存选择，但运行时回退；重新挂载后用户选择恢复，不自动续读旧句柄。

## 2. 锁屏模式：WALL-01

设置 → 锁屏与壁纸提供四种模式：

| 模式 | 行为 | 默认 |
| --- | --- | --- |
| 系统默认 | 固件内置黑白锁屏图 | 首次开机选中 |
| 自定义壁纸 | 用户图片，经裁切和灰阶预处理 | 用户应用后生效 |
| 当前书封面 | 使用最近正在阅读图书的有效封面，等比留白 | 用户主动启用 |
| 简洁锁屏 | 白底产品名与静态提示，无书名 | 可选 |

锁屏统一竖屏684×1216，横屏阅读也先安全结束显示任务再转竖屏锁页；唤醒恢复阅读方向和位置。短电源键和自动锁屏用相同资源路径。低电量关机可在保留壁纸基础上叠加明确静态原因；正在升级/写入时先执行原有保存屏障，不能因美化锁屏提前切电。

时钟、日期、电量、唤醒提示是可选静态叠加，默认仅简短唤醒提示；显示“锁屏时”的值，睡眠中不按秒/分钟唤醒刷新。时钟未校准时不显示假时间。用户可隐藏书名、封面和进度以保护锁屏隐私；“当前书封面”明确说明会让旁人看到阅读内容。

## 3. 壁纸上传：WALL-02

网页壁纸标签接受JPEG/PNG，单文件≤8MiB；基线JPEG≤16M源像素、每边≤8192，PNG/渐进JPEG≤1M源像素，沿用有界图像解码。不是把压缩文件小等同于解码内存小。透明PNG铺白；不接受GIF动画、远程URL或通用SVG。

网页提供宽高、大小与设备比例预览，可选“完整显示”与“铺满裁切”，手机/电脑上的预览不是面板实测灰阶。设备端最终独立验证格式和大小，不能相信浏览器输出；图片JPEG EXIF方向用有界元数据读取归一化，坏EXIF不越界，无法识别时提示用户旋转。

上传目标 `/sdcard/wallpapers/`，最多索引32张。无TF时壁纸原图上传不可用，但仍可选择内置模式与已有内部缓存壁纸。上传不立即设为锁屏，避免意外暴露图片；完成后在设备预览并应用。USB通过技术门后也可复制原图到该目录，退出重扫。

壁纸与书籍封面独立kind/目录/索引，删除封面不删壁纸，删除壁纸不删书籍。上传覆盖继承part/backup事务；同名新图以摘要更新资源身份。壁纸上传失败不改变当前锁屏。

## 4. 裁切与灰阶

设备预览页提供完整显示（contain、白色留边）、铺满裁切（cover）、90°旋转、裁切位置方向按钮、原图/增强对比度两个档位。默认完整显示，不裁掉照片边缘。裁切用离散方向步进和松手提交，250ms合并预览，不边拖动边整屏扫描。操作区在预览下方，触摸位置不与“应用”重叠。

处理顺序：方向归一化 → 按比例缩放/裁切 → 透明白底合成 → 灰阶与可选轻度抖动 → 4bpp量化 → 静态预览。叠加系统文字位于有白底保护的底部安全带，可关闭；不把黑字直接放在黑色照片上。

应用前显示实际684×1216目标的缩小预览；“应用”生成内部锁屏缓存成功后才切换选择。“取消”保留旧资源与设置。正文字体gamma不影响图片壁纸，壁纸预处理参数有独立版本。

## 5. 内部缓存与断电恢复

为避免锁屏时再读TF/解码大图，激活壁纸预先生成415872-byte原生4bpp位图。新增独立1MiB `wallpaper`分区，A/B两份位图加版本头/CRC/序号/尺寸/源摘要/裁切参数，合计约832KiB，剩余供文件系统与事务元数据；T01需实测格式化后可用空间与磨损均衡开销。应用时需存储屏障，不能只在NVS先写选中路径。

更新顺序：写非活动槽 → 同步 → 验CRC与尺寸 → 提交新序号/选择 → 保留上一有效槽。失败/断电选最高有效代；两份损坏使用系统默认，绝不使锁屏失败。只保留当前和上一版处理结果，不把32张原图搬入flash。壁纸分区不经USB导出，不用于存书。

原图在TF，已应用位图在内部缓存。拔卡或原图移动后锁屏仍用有效缓存，编辑页面提示“原图不可用”；恢复默认随时可用。“当前书封面”仅在封面已缓存且内存/介质允许时后台生成锁屏位图，不在每次翻页写flash；换书并完成有效预览后更新，首次生成失败保留旧缓存并提示未更新。

删除当前原图可保留内部已应用壁纸，确认文案说明这一点；要清除显示内容使用“移除自定义壁纸并恢复默认”，待显示完成与选择提交后再回收两个自定义槽。单纯取消选择不偷偷删除原图。

锁屏GC16前从内部槽读到显示owner目标帧，可按行复制，不额外保留常驻全屏壁纸帧；预处理属于reader/import互斥工作，复用现有图像预算。进入睡眠只需现成位图与静态UI叠加，不依赖正文font context。

## 6. API补充

统一POST `/api/v1/uploads` 增加kind `wallpaper`，与 `book/font/cover`共享上传状态机。GET `/api/v1/fonts` 返回有界目录与校验/轴/样例信息；DELETE `/api/v1/fonts/{id}` 只对未使用资源生效，使用中返回409并指向设备替代流程。GET `/api/v1/wallpapers` 返回原图与是否有有效激活缓存；DELETE `/api/v1/wallpapers/{id}` 删除原图需确认，返回缓存保留状态。

字体选择、壁纸裁切与应用初版在设备完成；网页负责上传、列表、样例/比例预览和原图管理，不绕过设备应用确认。所有API需配对授权，路径由kind映射到允许根目录，不能通过name写系统UI/OTA或私有壁纸分区。
