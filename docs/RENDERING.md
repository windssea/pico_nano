# 字体、段落、分页与墨水屏刷新

## 1. 分辨率与清晰度

面板逻辑尺寸 684×1216；按标称 4.7 英寸对角线推算约 `sqrt(684²+1216²)/4.7≈297 ppi`，须以面板有效尺寸核实，不能当实测 DPI。44 px 正文约 3.8 mm 高的 em、约 10.7 pt 参考值；真实可见字形高度取决于 font ascender/descender 和设计，不用 point size 代替真实排版度量。

字体直接以目标设备像素光栅化；不先低分辨率生成再放大，不用整页双线性缩放文字。灰阶抗锯齿是覆盖率，转换到 4bpp 时采用经真机校准的覆盖曲线。参考字体 gamma=0.6 是候选起点，M2 比较 0.6/0.8/1.0 后择优，不作为所有字体正确值。

三种呈现：清晰均衡（灰阶文字 GL16）；快速（二值文字 DU）；图片优先（灰阶/图像 GL16，必要 GC16）。快速模式按独立二值阈值渲染，不把边缘灰字无处理送 DU，防笔画丢失。

## 2. 字体系统

0.0.6实际字体port选择固定FreeType 2.14.3的TTF模块，理由是支持自定义预算/流式源并保持解析器上游维护，避免把stb头校验当不可信字体安全保证。当前真实度量/栅格/常驻UI子集与捕获已实现，变化轴UI、LRU/fallback链和上传安全验收仍待完成，见 [字体port](FONT_PORT.md)。

1. UI 字体常驻且覆盖全部 UI 文案；使用有许可证的固定字重中文子集。
2. 正文 TTF 存 TF，支持 TrueType glyf/loca；OTF/CFF、TTC、WOFF 初版不支持，导入明确提示。
3. 可变字体读取 fvar 真实 wght 范围，通过选定引擎的TT gvar接口实现受测变化；不只为单一字体写死 300–800。超出支持的 variation 能力以默认实例回退并提示。
4. fallback 顺序：用户主字体 → 同用户指定的完整 fallback 字体 → UI 字体 → 方框带缺字统计。UI 子集不是完整中文回退。
5. 静态字体字重通过另一字体文件选择；人工笔画扩张只作为后续可控“增强对比度”，不能冒充真实可变字重。

度量和光栅分离：cmap/hmtx/kerning（可用的 kern，复杂 GPOS 不承诺）常驻小表/有界缓存；分页测宽不触发整章 raster。cache_key 包含字体内容摘要、glyph id、px、variation、render_mode、gamma、engine_version；变设置失效相关缓存，保留不可变表。

字体校验从上传结构预检扩展到懒读取时校验 glyf 轮廓、复合深度、点数、variation 片段与整数边界；stb_truetype 不是不可信字体安全沙箱。异常字体必须在预算内失败，超复杂字形用 fallback；ASan/UBSan 与 fuzz 覆盖字体边界。必要时采用离线字体验证/裁剪工具，不能只校验 SFNT 头就宣称任意字体安全。

LRU 默认 1 MiB 文本模式、PDF 时 UI 字体 384 KiB 总预算；像素 cache 与字体文件 I/O cache 分开统计。预热可见页高频字与下一页，不扫描整本书全字符。TF 字体替换前正文 session 暂停并关闭源；UI 字体保持可画，完成后重新打开内容摘要匹配的新 font。

## 3. 排版规则

正文每行用基线对齐；行盒取最大 ascender/descender 与行距，混合标题和正文不按字符 top 简单拼接。中文标点禁则：闭括号/逗号/句号不做行首，开括号不做行尾，成对省略号/破折号优先整体；英文单词整体换行，超长 URL 允许字符边界切分并标记。数字单位尽量不拆，不能因此导致无穷回退。

两端对齐只分配有限伸缩，中文字符间伸缩不超过 0.08 em，英文词空格不超过 0.5 em 额外扩张；最后行左对齐。缩进仅段首；标题不继承正文首行缩进；诗歌保留换行；段前/段后用 max 而非简单双倍堆叠。图片保持纵横比，标题避免孤留页底；段落 widow/orphan 最少 2 行，有预算时执行，无可行方案允许拆分但不丢字。

语言支持基线：中文/日文横排、拉丁文本；竖排日文、ruby、复杂塑形和 RTL 列 P2。对受测 ruby 可先显示括注，不能无提示丢读音。

## 4. 分页与位置

输入=规范化 BlockStream＋FontMetrics＋LayoutSettings＋Viewport，输出分页节点与源锚点。

layout_key 必须包括 book_id、章节资源摘要、解析版本、字体/fallback 摘要、字号、轴实例、行距、段距、缩进、边距、对齐、语言规则、旋转、页脚占位、图片模式与排版版本。纯 gamma/灰阶呈现模式若不改字形度量，仅 bitmap_key 变化，不无谓重新分页。

先定位保存锚点所在工作窗口 → 当前页＋前后各一页 → 当前章节增量分页。可取消的 worker 每片段最多 10 ms 软件工作时间或一个 block（大 block 继续切分），然后检查 generation/取消/介质 epoch。当前页所需结果优先，全章总页数属于空闲任务。

长章的页索引分段到 TF：每段最多 512 page anchors，RAM 只保留当前段与邻段。末页跳转先用已存在索引；冷索引仍需渐进计算时显示“正在定位章节末尾”，允许取消，不向 UI 返回假末页。总书页数只在同一 layout_key 下算完所有章节才确定，不用百分比反推。

预排下一页与缓存上一页；后台字体光栅与当前显示扫描重叠时受 PSRAM 带宽限制，测到欠载就暂停预热直到 scan 完成，不能以“多核”推定无限并行加速。

## 5. 显示流水线与导航

```text
输入提交 → 合并导航意图 → reader 定位/排版 → 单独目标帧
          → display 验证 token → 波形/区域选择 → 扫描
          → 成功更新物理参考帧 → 完成事件 → 释放目标帧
```

三个角色位图：物理参考、当前目标、预绘制候选。对 epdiy 的具体 framebuffer/back_fb 归属 M0 核实，不能重复计算或让 worker 修改扫描中的 buffer。用 buffer lease 与 generation 防交叉写；扫描完成前不宣称 reference 已推进。

输入线程在刷屏时继续采集；翻页队列只保留一个导航意图。不会因为 5 次连点在 2 秒后继续翻 5 页。电源/取消/离书事件高于待翻页，但不在波形相位中间粗暴停屏；等待安全结束或走受控故障恢复。

## 6. 刷新策略表

| 内容变化 | 默认策略 | 定稿/强刷 |
| --- | --- | --- |
| 灰阶正文普通翻页 | GL16 全像素正文区域 | 每 12 页/严重损伤评分用 GC16，按场景校准 |
| 二值正文快速翻页 | DU，黑白独立位图 | 每 6/12 页强刷，切灰阶/图像先 GC16 |
| 控件按下、离散数值 | 小区域 DU，合并 damage | 停 350 ms 或达到 6 次后 GL16 定稿 |
| 封面/照片/PDF/漫画 | GL16 灰阶，合批更新 | 新页明显差异/累计损伤大时 GC16 |
| 新页面、旋转、唤醒、手动清屏 | GC16 | 重置损伤统计 |
| 页脚百分比/页码 | 独立小区域 DU | 与正文共批，避免重复 full scan |
| 二维码 | GC16 后保持黑白 | 扫描中不更新区域 |

已有波形默认 GC16 36 相、GL16 37 相，参考帧周期约 11.09 ms；约 430 ms 的说明包含实现开销。不能把局部面积比换算成线性提速：LCD 扫描可能仍扫整屏。每批 display job 尽量把同模式正文/页脚合并，只有需要不同波形时分开，并测额外扫描成本。

损伤评分输入：软刷新数、黑白变化量、反转次数、图片/文字类型；初版用确定计数策略，真机数据支持后才增加评分，不凭主观“AI 自动刷新”。温度变化先监测与降频/降档，不修改厂商波形表；面板工作温度/时序与已有文档比对后写正式支持范围。

仅驱动已验证的模式；不自行删波形相位追速度，不设置产品默认 ALL_DU。绘制错误或 line queue underrun：降到参考安全 pclk 12 MHz、清物理屏并以保留的目标帧恢复；重试一次仍失败显示诊断/进入保护，不无限全刷。

## 7. PDF 与图像调度

当前视口解码为条带，单独 scene/context 预算；普通翻页图像必须按需要加载，不能预解码整本漫画。PDF 下一页预取只在引擎 context 和总内存允许时执行；无空间先保当前页，宁愿冷页较慢也不崩溃。缩放仅渲染视口 clip，缓存当前倍率的相邻 tile，横屏最大尺寸也受全屏像素数约束。

正文内嵌图像属于分页语义：第一次布局就采用元数据获取的长宽与占位高度，解码成功不改变 block 高度，失败保留占位，防图片加载导致跳页。切换图片显示模式会改变 layout_key，应重新定位源锚点。

## 8. 性能测量

记录 input_received、intent_committed、layout_start/end、raster_end、display_enqueue/start/end、save_commit。定义“热翻页软件准备”为 intent_committed 到 display_enqueue；“总翻页”到 display_end；不是声称玻璃上的肉眼图像绝对稳定时刻。实际可见起始/残影用 ≥120 fps 摄影与照片对照。

常规 GL16 p95≤650 ms 的目标分配：软件 80 ms＋物理/扫描约 430–500 ms＋调度/供电余量；每项需要测。冷加载与跨章单独统计；不要把已缓存页冒充冷书打开。优化次序：无效 I/O → 度量缓存 → 源位置索引 → 预绘制 → 合批刷新 → 经验证的安全时序，不先超频。
