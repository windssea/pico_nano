# 家庭网络与局域网传书

0.0.53接入保存一个家庭WiFi并以STA模式传书。设备没有屏幕键盘，因此网络在热点传书的手机网页里保存；之后菜单出现“局域网传书”，手机与阅读器在同一网络时扫码打开网页。驱动层的STA生命周期见 [设备WiFi](DEVICE_WIFI.md)，热点入口见 [设备传输入口](DEVICE_TRANSFER_ENTRY.md)。只有主机/SDK-stub验证，真实路由器连接、2.4GHz兼容和吞吐未测。

## 保存与忘记

网页自动连接后，若设备支持（设备HTTP启用了配网出口），显示“家庭网络”面板：名称最多32字节UTF-8，口令为空（开放网络）或8–63个可打印ASCII。接口均需页面自动取得的会话令牌：

| 请求 | 结果 |
| --- | --- |
| GET `/api/v1/network` | `ssid`、`saved`、`pending`、`result`（none/ok/failed），从不含口令 |
| POST `/api/v1/network` `{ssid,password}` | 校验后排队，202；上一请求未处理409；格式错误400 |
| DELETE `/api/v1/network` | 排队“忘记”，202 |

PC开发服务没有此出口，返回404，面板隐藏。HTTP任务只把请求复制进控制层的单槽信箱，不做文件I/O；设备主任务在传输刷新时取出，取内部data的WRITE租约写入 `/data/progress/network.a/b`（PNJR A/B记录，载荷PNWC v1），再回报名称与结果供网页轮询。忘记网络写入空名称记录，不擦除文件。写失败以读回为准。

口令以明文保存在内部data分区（未启用flash加密），不写NVS、不进日志、不经HTTP回显；控制层信箱、配置和临时缓冲用后清零。只保存一个网络，不做扫描列表、企业认证或非ASCII口令。

## 局域网传书

打开菜单时读取已保存名称；有名称才显示“局域网传书：名称”。进入时与热点相同先保存并关闭正文、移交TF，读取口令填入STA配置后立即清零本地副本。驱动按既有规则在二十秒内最多尝试三次；成功后页面只显示打开网页的二维码、网络名称、网页地址，不显示任何WiFi口令。连接失败显示“无法连接已保存网络，可改用热点传书”，不会自动切换到热点；停止后返回原书。局域网会话中网页同样可以更新或忘记网络，下次进入生效。

## 断线、供电与介质检测

传书对象存在时主任务禁止自动锁屏/浅睡；电源键先停止传输，再按锁屏流程处理。STA传书启动后显式关闭WiFi modem sleep（WIFI_PS_NONE），减少省电唤醒引起的响应波动，代价是传书期间无线功耗增加。

短暂断连进入“正在连接”并复用驱动的有界重连。HTTP监听、会话令牌、工作任务和上传位置保留；重连仍是原IP则继续服务，IP改变或重连最终失败才终止旧网页地址的会话。此前会话层在首次断连时立即退出，提前截断了驱动重连；SDK-stub现在覆盖首个64KiB分块上传、断连、原IP重连与原偏移续传。

传输使用自有只读卡检测适配，FCA9555的P0.6确认无卡才返回介质失效状态（PN_STALE_MEDIA）；I²C读取失败返回PN_IO，禁止本次存储操作，控制任务最多等待一秒恢复，不调用会永久失效挂载缓存的BSP状态 getter。这样读取错误不会被报告成真实拔卡。真实拔卡仍立即结束会话，且不格式化、不重新初始化TF。截图中的失效提示与旧误判路径相符，但缺少该次设备日志，不能认定唯一根因。

用户反馈无重启，故本轮重点修复STA会话中断与检测误判。实际RF信号、供电与卡写入质量仍需刷入后对照验证。

## 验证

### 无线诊断（开发代码，未发布）

设备GET `/api/v1/status`增加 `wifi_ready`、`rssi_known`、已知时才出现的负值 `rssi_dbm`、`disconnects`、`reconnects` 和 `last_disconnect_reason`。计数限于当前联网会话，不跨重启保存。STA就绪后最多每秒采样一次信号；断线立即标记未知，过期值不作为当前信号回报。重连计数不包含首次取得IP；SDK断连原因码原样保留，不能单凭一个码断定供电根因。诊断不包含WiFi口令或会话令牌。

同源主机测试验证负RSSI不会变成无符号大数、未知信号省略值、断连原因与恢复计数，以及状态不回显口令。实机失败后可在浏览器打开上述地址留存状态；无线完全不可达时只能在恢复后查看同一会话的累计记录，最终会话关闭后记录释放。

### 2026-10-13 USB供电时响应排查

用户确认接电脑或充电器时网页响应异常、拔线恢复。当前构建启用了 `CONFIG_ESP_PHY_ENABLE_USB`；ESP-IDF v6.1 的 esp_phy/Kconfig明确指出USB PHY在部分目标上会干扰WiFi，关闭该选项可使用SDK规避。这是源码支持的候选原因，还没有电源纹波/RF或插拔对照测量，不能据此确认充电电路根因。

修正版关闭该选项，并由自有板级适配在AP/STA无线初始化前保存USB pad状态并暂停数据接口。完整关闭WiFi后恢复此前启用状态；初始化失败也恢复，停止失败则继续暂停，避免无线仍运行时重新启用USB。原先关闭的USB不会被擅自打开。不修改PMU、VCOM、SY7636A或USB存储所有权，USB供电/充电继续。网络传书期间USB串口会暂时消失；需先退出传书，再连接网页安装器升级。

SDK-stub回归验证正常关闭、启动失败、网络超时、停止失败重试、原先pad/clock关闭的恢复边界。测试证明代码时序，不证明物理干扰消除；仍需用户在接电脑、接充电器、拔线三种状态下复验网页加载、自动连接、上传和停止，并确认退出后USB可重新枚举。

`python tools/dev.py host`：network_store覆盖校验边界（长度、可打印ASCII、UTF-8、空名称）、往返、开放网络、忘记、清零、未知版本与长度不符；device_transfer_http覆盖未启用404、缺会话令牌401、保存交给出口且响应不含口令、忙409、六类非法输入400、开放网络、状态查询不含口令、忘记及关闭出口；device_transfer覆盖信箱为空与回报名称长度；transfer_view覆盖局域网页面与六槽菜单命中。设备菜单/保存/STA装配只经两套ESP-IDF构建编译链接，手机网页面板只做了语法检查，未在真实手机或设备上运行。
