# 家庭网络与局域网传书

0.0.53接入保存一个家庭WiFi并以STA模式传书。设备没有屏幕键盘，因此网络在热点传书的手机网页里保存；之后菜单出现“局域网传书”，手机与阅读器在同一网络时扫码打开网页。驱动层的STA生命周期见 [设备WiFi](DEVICE_WIFI.md)，热点入口见 [设备传输入口](DEVICE_TRANSFER_ENTRY.md)。只有主机/SDK-stub验证，真实路由器连接、2.4GHz兼容和吞吐未测。

## 保存与忘记

网页配对后，若设备支持（设备HTTP启用了配网出口），显示“家庭网络”面板：名称最多32字节UTF-8，口令为空（开放网络）或8–63个可打印ASCII。接口均需配对令牌：

| 请求 | 结果 |
| --- | --- |
| GET `/api/v1/network` | `ssid`、`saved`、`pending`、`result`（none/ok/failed），从不含口令 |
| POST `/api/v1/network` `{ssid,password}` | 校验后排队，202；上一请求未处理409；格式错误400 |
| DELETE `/api/v1/network` | 排队“忘记”，202 |

PC开发服务没有此出口，返回404，面板隐藏。HTTP任务只把请求复制进控制层的单槽信箱，不做文件I/O；设备主任务在传输刷新时取出，取内部data的WRITE租约写入 `/data/progress/network.a/b`（PNJR A/B记录，载荷PNWC v1），再回报名称与结果供网页轮询。忘记网络写入空名称记录，不擦除文件。写失败以读回为准。

口令以明文保存在内部data分区（未启用flash加密），不写NVS、不进日志、不经HTTP回显；控制层信箱、配置和临时缓冲用后清零。只保存一个网络，不做扫描列表、企业认证或非ASCII口令。

## 局域网传书

打开菜单时读取已保存名称；有名称才显示“局域网传书：名称”。进入时与热点相同先保存并关闭正文、移交TF，读取口令填入STA配置后立即清零本地副本。驱动按既有规则在二十秒内最多尝试三次；成功后页面只显示打开网页的二维码、网络名称、网页地址与配对码，不显示任何WiFi口令。连接失败显示“无法连接已保存网络，可改用热点传书”，不会自动切换到热点；停止后返回原书。局域网会话中网页同样可以更新或忘记网络，下次进入生效。

## 验证

### 2026-10-13 USB供电时响应排查

用户确认接电脑或充电器时网页响应异常、拔线恢复。当前构建启用了 `CONFIG_ESP_PHY_ENABLE_USB`；ESP-IDF v6.1 的 esp_phy/Kconfig明确指出USB PHY在部分目标上会干扰WiFi，关闭该选项可使用SDK规避。这是源码支持的候选原因，还没有电源纹波/RF或插拔对照测量，不能据此确认充电电路根因。

修正版关闭该选项，并由自有板级适配在AP/STA无线初始化前保存USB pad状态并暂停数据接口。完整关闭WiFi后恢复此前启用状态；初始化失败也恢复，停止失败则继续暂停，避免无线仍运行时重新启用USB。原先关闭的USB不会被擅自打开。不修改PMU、VCOM、SY7636A或USB存储所有权，USB供电/充电继续。网络传书期间USB串口会暂时消失；需先退出传书，再连接网页安装器升级。

SDK-stub回归验证正常关闭、启动失败、网络超时、停止失败重试、原先pad/clock关闭的恢复边界。测试证明代码时序，不证明物理干扰消除；仍需用户在接电脑、接充电器、拔线三种状态下复验网页加载、配对、上传和停止，并确认退出后USB可重新枚举。

`python tools/dev.py host`：network_store覆盖校验边界（长度、可打印ASCII、UTF-8、空名称）、往返、开放网络、忘记、清零、未知版本与长度不符；device_transfer_http覆盖未启用404、未配对401、保存交给出口且响应不含口令、忙409、六类非法输入400、开放网络、状态查询不含口令、忘记及关闭出口；device_transfer覆盖信箱为空与回报名称长度；transfer_view覆盖局域网页面与六槽菜单命中。设备菜单/保存/STA装配只经两套ESP-IDF构建编译链接，手机网页面板只做了语法检查，未在真实手机或设备上运行。
