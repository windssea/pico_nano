## 自动保存调用顺序

`pn_save_policy_t`固定大小，无动态分配；存储owner串行使用，不能在ISR或多个任务并发改结构。init复制journal IO和expected book_id，可传已恢复baseline；baseline为空时第一次presented才建立dirty位置。baseline必须已经落盘，不能把未保存位置标成clean。

显示owner确认当前token且物理呈现成功后，才调用presented。位置变化会dirty；`page_turn=true`仅用于实际有效翻页，计数最多饱和到5。重复同位置不重新计数；目录/书签跳转和排版位置更新可用false，仍参与时间保存。错书身份返回STALE_JOB，原文件大小不一致或时钟倒退返回INVALID。输入必须是已解析的有效字符边界。

owner定期tick，用同一单调毫秒时钟。5次有效翻页或首个未保存变化满30000ms先到者触发；后续位置变化不能延后dirty_since。只有同步读回成功才清dirty/计数；失败保留最新位置。自动失败重试至少间隔1000ms，等待时tick返回BUSY，避免每轮写坏存储；flush可绕过等待立即重试。清理前的离书/锁屏请求必须先flush，错误不能继续切电。

这是同步保存策略，不是带deadline的电源屏障；fwrite/fsync可能阻塞，未来存储worker/看门狗/取消路径仍必需。失败后应保留策略对象直到处理完成，不可离书先销毁dirty状态。实际文件适配的WRITE租约应由存储服务在保存短窗口取得与释放，不能为策略整个生命周期占有WRITE而阻塞阅读；目前策略不自动取得租约。

## 单书签持久操作

每个书签独立A/B文件。pn_bookmarks管理器已经提供ID分配、列表重建、分页、同位置去重和100条上限；单条codec仍可以独立使用。0.0.11已接TXT列表/编辑/确认入口，完整格式及硬件验收仍待完成。

create仅允许两槽均不存在，已有记录返回BUSY，损坏/未知版本不覆盖。label最多48 UTF-8 bytes，允许空名称由上层生成默认名，拒绝非法UTF-8、过长、ASCII控制字符；读回校验终止/零填充。rename先验证book_id/ID，不修改位置。position返回原TXT位置，由解析/导航执行跳转，已删除返回EMPTY并保持输出。

delete保存deleted墓碑，幂等删除返回OK，不删除文件或修改进度journal；同一ID/路径不得立即复用。上层只有确认提交才从列表移除，保留墓碑供索引恢复。底层同步失败可能已经提交；失败后重新load确认，不能假定错误必然意味着旧状态。最新槽损坏仍按A/B规则回退到旧有效代，未来索引/恢复UI需处理可能回退的删除状态，不能保证遭遇任意介质损坏仍保留删除结果。

### 书签载荷schema=1

所有整数小端，固定120 bytes，由外层PNJR提供序号与CRC。

| 字节位置 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII PNBM |
| 4 | 2 | schema=1 |
| 6 | 2 | flags：0有效、1删除；其他值UNSUPPORTED |
| 8 | 32 | 原文件SHA-256 |
| 40 | 8 | source_offset |
| 48 | 8 | source_size |
| 56 | 4 | 非零paragraph_version |
| 60 | 2 | encoding，同TXT位置codec |
| 62 | 2 | label字节数0–48 |
| 64 | 8 | 非零书签ID |
| 72 | 48 | label UTF-8，剩余字节必须0 |

错书或错ID返回STALE_JOB；错误不更新输出。没有永久页码。不同格式需后续独立有版本的载荷，不能把EPUB/PDF语义位置塞入TXT字节offset。

## 每书100条管理与阅读器接入

pn_bookmarks_init绑定已挂载内部存储的租约和已存在root，以原文件SHA命名独立`<SHA>.marks`目录。绑定只读不创建目录；第一次添加才创建该目录。root是可信owner路径，目录加记录路径必须落在384byte路径缓冲内，过长返回LIMIT。READ可以列出/取位置，写操作要求WRITE；调用方保持租约有效并串行操作。

条目路径是16位小写十六进制ID加.a/.b，ID从1递增、墓碑参与最大ID计算。目录直接作为可恢复索引，无额外中心索引事务。每次分页或添加扫描记录，最多100条有效项；同位置返回既有ID，不改名称；已满返回LIMIT，删除后新条目用新ID。UINT64_MAX已观察后禁止绕回。最新槽损坏按既有A/B规则回退；.a消失时可从.b恢复并入列表，不重复列出成对文件。

条目按ID升序，调用方提供1至100条输出容量，可按末条ID请求下一批。内存只与输出容量有关，不整库分配；时间与墓碑/记录总数有关，没有异步取消或快速持久索引。墓碑暂不回收，频繁添加删除最终可能占满data，错误会保留文件；后续压缩/空间回收必须有独立可靠提交方案，不能直接删墓碑来复用ID。无永久删除数据的自动修复。

合法命名的记录遇到双槽损坏、未知版本、错身份或源长度/解析策略不一致会阻止列表/添加，错误count=0，不把坏记录当不存在。主机拒绝记录及书签子目录符号链接。其他名称不是书签记录，不参与索引。没有记录目录视为空列表，目录I/O失败不视为空。

共享阅读器提供bookmark_add/list/rename/delete/jump/return API。add只取成功显示页首，尚未显示返回EMPTY；无state-dir不提供持久书签。jump复用真实解析/显示确认，只有本次确认成功才建立返回点；return成功确认才消费返回点。不能只比较跳转前后offset，跳转同一位置时也可能显示失败。保存失败可能发生在显示确认之后，这时位置已变化、dirty仍保留，返回点按确认结果保存。改名/删除不写进度；下次打开从进度恢复，不从书签恢复。

主机`bookmarks`测试覆盖100条、重复位置、分页、重开、改名、墓碑、错书、只读、过期租约、.b单槽、最新槽损坏、坏条目保留和ID耗尽。`reader_bookmarks`使用真实TXT/TTF/持久文件验证未显示拒绝添加、失败跳转（含同一位置）、返回失败可重试、跨会话改名/列表和删除不改变续读。共享设备UI已有接线，软件测试不等于真机断电/触摸/纸屏验收。
