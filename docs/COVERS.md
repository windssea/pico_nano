# 书架封面与缓存

0.0.49起书架列表显示真实封面缩略图。本页是封面提取、空闲队列和TF缓存的维护契约；格式层的完整封面优先级目标见 [格式设计](FORMATS.md) 第8节，书架布局目标见 [界面与交互](UI_UX.md)。当前只在主机/SDL验证，没有真机速度、内存或面板观感证据。

## 来源与当前范围

| 格式 | 当前来源 | 未覆盖（仍显示排版占位卡） |
| --- | --- | --- |
| EPUB | OPF的cover-image或EPUB2 meta cover；无声明时严格文件名cover.jpg/jpeg/png候选 | guide封面页内首图、spine首页大图 |
| TXT | 同目录同名侧车，顺序 `.cover.jpg`、`.cover.png`、`.jpg`、`.png`，首个存在者决定结果 | 网页上传绑定内容身份的封面 |
| PDF/FB2/CBZ | 不提取 | 格式本身尚未接入 |

图片按内容签名送PNG/JPEG解码器，不看扩展名或MIME；侧车写成.jpg但内容不是图片时为UNSUPPORTED，显示占位卡。EPUB封面必须通过图片EOF与ZIP资源CRC才算成功。原书和侧车只读。

## 缩略图

槽位72×100、4bpp，与当前六行列表的封面框一致；目标三列网格的184×256尚未实现。图片按contain缩放并居中，留白为白色，不裁书名、不拉伸。先按最多4倍超采样绘制到不超过128KiB的临时帧，再做k×k均值缩小，避免最近邻直接缩小的锯齿；原图比目标还小时不超采样。暂未做封面专用的有序抖动。

pn_cover_render在独立子池中完成全部临时分配，子池上限由调用方给出，并同时计入父pool。任何非OK结果都不改调用方缩略图，结束时本次分配全部释放；主机测试对每个分配点注入失败验证这一点。

## 内存与大图

渐进式JPEG必须为整图保存全部DCT系数，与缩略图大小无关。实测私有样本《绍宋》封面为1092×1533、4:2:0渐进式，单次提取pool峰值5383466字节（主机ASan构建计费，含ZIP/出版物模型），2MiB上限会得到NO_MEMORY。因此预算不是固定常量：

- 设备：书架空闲时使用整机pool剩余量减512KiB保留，书架状态本身约数十KiB；6MiB pool下此类封面在账面上可容纳。
- SDL：使用书库窗口pool剩余量。
- 超出预算记FAILED并显示占位卡，书仍可打开；NO_MEMORY不写缓存，下次进入书架会重试。

PSRAM碎片下能否一次取得libjpeg约3.4MiB的连续系数块、解码耗时与看门狗余量都必须真机测量；没有结果前不承诺大封面在设备上一定显示。基线JPEG若改用DCT域缩放可大幅降低内存与耗时，尚未实现。

## 空闲队列与刷新

调用方拥有pn_shelf_covers_t（六个3600字节槽及状态）。换页时：

1. pn_shelf_covers_reset：TXT/EPUB置PENDING，其他NONE。
2. pn_shelf_covers_cached：只读缓存填充命中项，未命中保持PENDING。随后绘制书架，缓存命中的封面首帧即可见，墨水屏不因封面二次刷新。
3. 空闲且无触摸时每次调用pn_shelf_covers_step解码一条。整页队列结束且有新封面时设备做一次GL16重绘，不逐本闪屏。

step内部短暂取得READ读书和缓存，需写缓存时另取WRITE；他人持有WRITE返回BUSY，介质失效返回STALE_MEDIA，两者都保留PENDING，设备随后停止本页队列。传输、锁屏、状态页和阅读菜单期间设备不运行队列。单本解码在设备worker上同步进行，大封面首次解码期间触摸轮询会暂停，缓存后不再发生。

## TF缓存

设备目录 `/sdcard/.readpico/covers`，按需创建 `.readpico` 与 `covers`。SDL只有显式 `--cover-cache DIR` 才写缓存，默认只解码，不写用户样本目录或状态目录。

每本书一个文件，名为原路径FNV-1a 64位的16位十六进制加 `.pnc`。小端记录：

| 字段 | 字节 |
| --- | --- |
| 魔数 `PNCV` | 4 |
| 缓存版本（当前1）、宽、高 | 各2 |
| 状态（READY/NONE/FAILED）、提取结果码 | 各1 |
| 键：书大小、书mtime、侧车序号（无为0xff）、侧车大小、侧车mtime | 8+8+1+8+8 |
| 路径长度与完整UTF8路径 | 2+N |
| 像素（仅READY） | 3600 |
| 以上全部的CRC32 | 4 |

只缓存由内容决定的结论：OK、EMPTY、UNSUPPORTED、CORRUPT；NO_MEMORY、IO、LIMIT等可能下次成功的结果不缓存。键或路径不符视为未命中；魔数、版本、长度或CRC不符视为损坏并重新解码覆盖。写入先写 `.tmp` 并fflush/fsync，再删除旧文件后rename；中途掉电最多失去该条缓存，CRC拒绝残片。缓存目录可整体删除，下次重建，不影响原书、进度或书签。

缓存键使用路径、大小与mtime的快速检测，而非FORMATS中设计的内容SHA；封面缓存只影响显示，不参与续读身份。代价是同大小且mtime不变的替换无法察觉，删除缓存目录即可重建。改变缩略图算法或尺寸必须提高PN_COVER_CACHE_VERSION。

## 验证

- `python tools/dev.py host`：cover测试覆盖EPUB3声明、EPUB2 meta、文件名候选、无封面、ZIP CRC损坏、TXT侧车/无侧车/伪图片；宽/高图contain留白与灰阶数值；全部分配点失败注入、小预算与介质失效；真实目录队列、书架绘制、READ/WRITE占用与失效保持PENDING；缓存首写、命中（原书封面已损坏但大小/mtime不变仍显示缓存）、mtime失效、CRC损坏重建、侧车删除改键、无临时残留，以及缓存预取与逐条结果逐字节一致。
- `python tools/dev.py sdl`：cover_window在dummy窗口验证空闲队列、单次重绘、显式缓存写入与重启命中，未指定目录时不写盘。
- 设备main的队列装配只由两套ESP-IDF构建检查编译链接；无真机执行证据。
