0.0.49起书架列表显示真实封面缩略图。本页是封面提取、空闲队列和TF缓存的维护契约；格式层的完整封面优先级目标见 [格式设计](FORMATS.md) 第8节，书架布局目标见 [界面与交互](UI_UX.md)。当前只在主机/SDL验证，没有真机速度、内存或面板观感证据。

## 缩略图

集中上传目录规则见 [存储卡目录](SD_CARD_LAYOUT.md)。TXT/EPUB位于books目录时先匹配卡根covers中的同名原图；旧同目录侧车继续兼容，EPUB最后回退内嵌封面。v4已加入验证过的OPF作品名与作者，当前v5另加入失败预算并采用降采样，旧缩略图自动重建，缓存键同时包含外置来源序号、大小与mtime。

W00核对最新源码：PN_COVER_WIDTH/HEIGHT已经是184×256、4bpp，每张23552字节，72×100属于旧基线。当前网格与列表使用共用槽后按各自视框采样；1.0仍需按布局独立尺寸/算法key和整机预算验证，不能把旧文档的“小槽”估算当现有成本。图片按contain缩放居中，留白为白色；最多4倍超采样且临时帧不超过128KiB，再做均值缩小，原图较小时不超采样。封面专用有序抖动仍待评估。

pn_cover_render在独立子池中完成全部临时分配，子池上限由调用方给出，并同时计入父pool。任何非OK结果都不改调用方缩略图，结束时本次分配全部释放；主机测试对每个分配点注入失败验证这一点。

## 内存与大图

渐进式JPEG必须为整图保存全部DCT系数，与缩略图大小无关。实测私有样本《绍宋》封面为1092×1533、4:2:0渐进式，单次提取pool峰值5383466字节（主机ASan构建计费，含ZIP/出版物模型），2MiB上限会得到NO_MEMORY。因此预算不是固定常量：

- 设备：书架空闲时使用整机pool剩余量减128KiB保留，仍受原6MiB pool及池外启动安全余量限制。未扩大全局阅读预算。
- SDL：使用书库窗口pool剩余量。
- 超出预算记FAILED并显示占位卡，书仍可打开；NO_MEMORY连同失败预算写缓存，同等或更小预算不重复转换，预算增长时重试。

2026-10-13增加IDCT阶段1/2、1/4、1/8降采样，保持输出覆盖目标，再按原contain与灰阶流程缩小。渐进系数分配限制为256KiB块，减少连续PSRAM要求，仍保留整图系数的总内存成本，不创建临时文件或手改vendor。原创1092×1533渐进图测试最大底层分配256191字节；带481章的原创EPUB封面提取峰值5402734字节，在模拟700000字节常驻与128KiB余量后的5460384字节预算内成功。这是主机pool计费，真实PSRAM碎片、看门狗、耗时与面板必须上板复验；《绍宋》原件路径尚待提供，不能据此宣称原书真机问题已解决。

## 空闲队列与刷新

调用方拥有pn_shelf_covers_t（最多八个可见槽及一个继续阅读槽，像素净成本211968字节，另有9KiB作品元数据、模型/状态；[书架外观](SHELF_APPEARANCE.md)支持每页6/8本与静态样式）。换页时：

1. pn_shelf_covers_reset：TXT/EPUB置PENDING，其他NONE。
2. pn_shelf_covers_cached：只读缓存填充命中项，未命中保持PENDING。随后绘制书架，缓存命中的封面首帧即可见，墨水屏不因封面二次刷新。
3. 空闲且无触摸时每次调用pn_shelf_covers_step解码一条。整页队列结束且有新封面或作品元数据时设备做一次GL16重绘，不逐本闪屏。

step内部短暂取得READ读书和缓存，需写缓存时另取WRITE；他人持有WRITE返回BUSY，介质失效返回STALE_MEDIA，两者都保留PENDING，设备随后停止本页队列。传输、锁屏、状态页和阅读菜单期间设备不运行队列。单本解码在设备worker上同步进行，大封面首次解码期间触摸轮询会暂停，缓存后不再发生。

## TF缓存

设备目录 `/sdcard/piconano/.readpico/covers`，由`PN_SD_COVER_CACHE`定义并按需创建父目录。SDL只有显式 `--cover-cache DIR` 才写缓存，默认只解码，不写用户样本目录或状态目录。

每本书一个文件，名为原路径FNV-1a 64位的16位十六进制加 `.pnc`。小端记录：

| 字段 | 字节 |
| --- | --- |
| 魔数 `PNCV` | 4 |
| 缓存版本（当前5）、宽、高 | 各2 |
| 状态（READY/NONE/FAILED）、提取结果码 | 各1 |
| 键：书大小、书mtime、侧车序号（无为0xff）、侧车大小、侧车mtime | 8+8+1+8+8 |
| 当时的解码预算（内存失败时用于重试判断） | 8 |
| 路径长度与完整UTF8路径 | 2+N |
| 已验证作品名与作者，空串回退 | 512+512 |
| 像素（仅READY，当前184×256/4bpp） | 23552 |
| 以上全部的CRC32 | 4 |

EPUB在同次出版物解析中取得title/creator，即使没有内嵌封面也保存元数据；外置封面存在时仍验证OPF。元数据未取得时不持久缓存该EPUB结论，避免暂时的内存/媒体失败使作者永久缺失。所有字符串必须有界并以NUL结束，CRC覆盖元数据。

缓存内容结论OK、EMPTY、UNSUPPORTED、CORRUPT；NO_MEMORY另记失败预算，同等或更小预算复用失败，预算增长则重试。首帧预取没有解码预算，内存失败槽保持PENDING，空闲step决定是否重试。IO、LIMIT不缓存。v5使旧缩略图和旧失败结论重建；键或路径不符视为未命中，魔数、版本、长度或CRC不符视为损坏。写入先写 `.tmp` 并fflush/fsync，再删除旧文件后rename；中途掉电最多失去缓存，CRC拒绝残片。清缓存不影响原书、进度或书签。

缓存键使用路径、大小与mtime的快速检测，而非FORMATS中设计的内容SHA；封面缓存只影响显示，不参与续读身份。代价是同大小且mtime不变的替换无法察觉，删除缓存目录即可重建。改变缩略图算法或尺寸必须提高PN_COVER_CACHE_VERSION。

## 验证

异步输入中断封面工作时，槽继续保持PENDING，取消不写失败缓存；再次空闲时可重新解码。收到输入不重置整页封面队列。见[异步阅读](ASYNC_READING.md)，cover回归包含处理中断后原像素不变、租约/池归零及重试结果一致。

- `python tools/dev.py host`：cover测试覆盖EPUB3声明、EPUB2 meta、文件名候选、无封面、ZIP CRC损坏、TXT侧车/无侧车/伪图片；宽/高图contain留白与灰阶数值；全部分配点失败注入、小预算与介质失效；真实目录队列、书架绘制、READ/WRITE占用与失效保持PENDING；缓存首写、命中（原书封面已损坏但大小/mtime不变仍显示缓存）、mtime失效、CRC损坏重建、侧车删除改键、无临时残留，以及缓存预取与逐条结果逐字节一致。
- `python tools/dev.py sdl`：cover_window在dummy窗口验证空闲队列、单次重绘、显式缓存写入与重启命中，未指定目录时不写盘。
- 设备main的队列装配只由两套ESP-IDF构建检查编译链接；无真机执行证据。
