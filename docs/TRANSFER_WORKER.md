# 有界传输工作任务

`pn_transfer_worker` 为共享传输服务增加专用工作任务、独立事务池和单请求槽。PC HTTP worker已使用真实pthread任务；ESP-IDF编译使用FreeRTOS分支。设备热点、页面与介质交接后续已接入，不能把编译当成设备传输运行证据。

## 进入与所有权

启动前必须关闭阅读、TF字体、书库扫描和USB消费者，确认共享media没有租约，再移交给传输任务。任务捕获同一个media指针，绝不新建第二个介质服务。移交期间主界面不能查询/改变其租约或代次、扫描TF、重挂载卡；可绘制常驻字体与读取锁保护的任务状态。检测到拔卡后应先请求任务停止，确认归还介质后再执行已有detach/remount流程。

事务池独立于UI池，只由工作任务访问；底层allocator必须线程安全，不能把UI的pn_pool当成分配回调。ESP默认分配器明确使用PSRAM；FreeRTOS互斥、通知和32KiB工作栈由系统分配。固定上下文包含一份64KiB请求数据槽，不计入事务池上限；主机HTTP另外保留自身64KiB管道接收缓冲。pool_peak只代表事务池，不代表整机内存。

启动分配失败或私有池不足会清理上下文并报告错误。启动失败不会挂载/格式化卡或取得写租约。设备使用 [FAT适配](DEVICE_TRANSFER_STORAGE.md) 提供固定根与平台ctx，所有引用在任务关闭前保持稳定。

## 请求与停止

execute在短锁内复制命令和CHUNK最多64KiB数据，然后由独立任务调用 [同源服务](TRANSFER_SERVICE.md)。调用方同步等待已接收请求完成；并发第二个请求返回BUSY，不无限排队、不分配整本缓存。同步接口不提供超时后提前释放对象的捷径；网络断开也要等本次调用完成。

request_stop只关闭接收入口并通知工作任务，不等待文件校验或强杀任务。新的合规请求返回CANCELLED；已接收命令完成后，任务关闭所有上传消费者、确认事务池和介质租约已释放，发布STOPPED。状态快照由互斥保护，不从界面线程读取活动pool/media。

完整退出顺序为：关闭认证/新请求入口 → request_stop → 停止并join网络调用方 → 确认工作任务停止 → close释放上下文 → 将media归还界面。close期间不得再进入execute/state等API。失败状态不能宣称已归还介质；不能删除仍活动的对象、强杀工作任务或卸载卡来绕过停止屏障。FreeRTOS任务在发布停止状态并解锁后不再访问上下文，其栈由idle回收。

## 验证边界

`python tools/dev.py host` 的transfer_worker使用真实pthread与POSIX文件，故意把I/O阻塞在同步回调，验证状态读取和stop立即返回、并发BUSY、停止后CANCELLED且错误不改reply、已接收请求继续完成、关闭归还介质、独立池分配失败无泄漏，以及重新开启后的持久续传和TXT安装。CTest设30秒上限，避免停止死锁被当成无期限测试。

transfer_http通过实际TCP和这条线程路径继续验证完整上传、重启、覆盖、取消及字体/图片。ESP-IDF两套配置使用真实FreeRTOS接口编译；仍须在设备上检查调度、任务栈高水位、PSRAM、停止耗时和功耗。PC的线程测试不证明这些硬件门通过。

PC HTTP服务关闭时停止接收连接，再通过非daemon请求线程与block_on_close等待已接收处理结束，最后关闭原生管道。transfer_http额外阻塞一条已接收请求，确认server_close没有提前返回；解除阻塞后请求、HTTP线程和原生任务均可正常结束。
