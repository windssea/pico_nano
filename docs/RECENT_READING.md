# 最近20本与继续阅读

0.0.12加入持久最近20本和设备/PC入口。格式记录可识别TXT/EPUB/PDF/FB2/CBZ，当前实际阅读仍只有TXT；不能把最近元数据当成其他格式解析已实现。

书架顶部“最近”切到最近列表，“全部”回文件列表；“继续”打开最近一本。PC键R切换、C继续，其余六行列表的键盘/鼠标/设备触摸操作不变。近期顺序是最近在前，内容SHA去重，重新从另一文件名打开相同内容会更新该实例路径；第21本原子移除最旧条目。不依赖RTC，重启不会把新会话的低uptime排在老会话之前。

只在当前页面真正确认显示后加入记录；失败呈现、仅打开文件不算阅读。离书/锁屏先保存逐书位置，再更新历史预览，更新失败保留会话供重试。首次历史写失败不撤销已经显示的正文，状态可查询；后续关闭仍要求完成历史屏障。历史损坏/未知版本不自动清理，可能阻止关闭，恢复引导与清历史确认入口仍待补齐。

继续时先重新读取原文件SHA，再与历史的期望SHA比较，匹配后才呈现/恢复进度。同路径换了内容会拒绝继续原书；用户仍可从全部书架打开新内容。路径消失或TF不可用不移除历史；当前不会按摘要自动搜索移动后的文件，需用户从全部书架重新选择该内容来更新路径。UI尚未逐行标注可用性/重新定位。

历史中的预览是0..10000万分数或未知65535，不是永久页码或恢复锚点。TXT预览按原字节范围估算；实际续读使用已绑定相同内容的逐书A/B源位置。崩溃或断电时预览可能比逐书位置旧，不覆盖真实进度。历史更新目前只在首次呈现和关闭发生，不因每个tick/翻页都写大快照；首条/路径/预览完全相同时不重复写。

## 两层持久格式

现有PNJR小记录不改。新的PNBL schema1用于有界大快照：magic4、schema2、flags2=0、payload长度4、非零序号8、payload、CRC32四字节；整数小端，CRC覆盖20字节头及payload。payload最大24576bytes，写另一个槽、fsync、读回验证。最新坏槽可回退到旧完整槽；未知版本/flags/I/O阻止猜测，两有效槽相同序号不同内容视为损坏。首次写中断且无旧有效槽会返回损坏，不自动当成空记录。

payload为PNRH/schema1/count（8bytes头），每条固定1072bytes：SHA32、原文件大小8、format2、预览2、路径长度2、reserved2=0、1024byte零填充路径。最多20条，总payload21448bytes，文件最多21472bytes，A/B约43KB。路径不截断，最多1023UTF-8bytes，非法UTF-8/控制字符/重复SHA/非零填充/不符长度拒绝恢复。很长的显示文件名可在UTF-8字符边界省略，实例路径与身份仍完整。

设备文件位于/data/progress/recent.a和recent.b，PC位于--state-dir。使用既有受租约保护的文件port，目录由已确认存储owner准备；不挂载、格式化、清NVS或访问VCOM。root为可信内部路径，不能从未验证上传参数直接指定。大型codec通过pn_pool分配临时缓冲，不放在worker栈；20条更新峰值约百KB额外池开销，仍需整机上板测峰值和时延。当前单owner同步I/O，不是统一异步存储服务或10ms时间片保证。

完整快照同时提交顺序、路径与预览，没有分片中心索引；旧20条或新20条是完整代，不应出现半条路径或混合顺序。历史淘汰不删电子书、逐书进度或书签。清历史/数据修复需以后明确确认，不能用挂载失败自动格式化替代。

## 可复跑验证

```powershell
python tools/dev.py host
python tools/dev.py sdl
python tools/dev.py firmware-ci
python tools/dev.py firmware-board
python tools/dev.py docs
```

blob测试对2KiB大记录每个字节切点模拟另一槽中断，验证旧或新完整记录及不确定提交；另测完整24KiB、未知版本和分配失败回收。recent用真实文件验证25本后保留20、别名去重/1023byte路径/重开/过期租约。reader_recent验证失败呈现不入历史、成功显示后记录、关闭预览更新、写失败保留与重试。SDL recent_window验证跨进程继续原位置以及同路径更换内容后拒绝旧历史。软件中断模型不证明真实flash随机断电、VFS同步或纸屏触摸/性能已验收。

封面、其他格式定位、移动文件查找、历史故障引导/清空确认、字体管理/壁纸/快速传书和电源服务继续保留在原第一版范围内。
