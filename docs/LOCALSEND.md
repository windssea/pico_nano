# LocalSend 接收模式

用户已要求增加与官方 LocalSend 客户端互通的传书方式。整文件接收基础层与 [元数据/会话核心](LOCALSEND_SESSION.md) 已实现；HTTP服务、发现、HTTPS与中文接收确认尚未接入，不能使用官方客户端传书。现有网页上传、热点与家庭网络传书继续保留；不能把网页扫码或核心测试描述成 LocalSend 互通。

## 协议与产品范围

协议来源为 [LocalSend 官方协议 v2.2](https://github.com/localsend/protocol/blob/62bd3406ec80d62f2ed46269cdc06c4dcc391083/README.md)，核对日期 2026-10-11。首期实现接收端，设备在传输页由用户开启，退出或锁屏时按现有停止屏障关闭。设备名“小纸 Pico”，接收已支持的 TXT/EPUB、TTF、JPEG/PNG；PDF/FB2/CBZ在阅读内核支持前拒绝，不按扩展名假装支持。

目标为同一家庭网络下，官方 Windows/Android/iOS 客户端发现设备、选择文件、设备确认后接收。热点模式另外验证手机路由与组播行为，不以家庭网络结果代替。初期不实现反向下载、剪贴板或任意文件导入。

## 接入边界

所有资源遵守 [存储卡目录](SD_CARD_LAYOUT.md)，必须通过共享安装层路由到books/fonts/covers/wallpapers；LocalSend不能直接写客户端路径。图片在接收确认时明确选择封面或锁屏图片。

- 默认 UDP 组播 224.0.0.167:53317，服务端口 53317；实现 register、info、prepare-upload、upload、cancel。声明 download=false。组播不可用时验证客户端的 register 探测路径。
- 接收前展示发送方、文件数与总大小，默认等待确认，支持拒绝与取消。会话及逐文件令牌使用系统随机源，绑定发送方地址并限制有效期。单个活动会话、有界元数据、文件数/大小/剩余空间限制，路径仅取安全文件名。
- HTTPS及自签证书指纹按官方协议处理，先测握手内存与客户端互通；设备端支持是否足够需实际 SDK 构建与样机验证。HTTP是协议允许的模式，但不能把明文模式当作加密，不能跳过既有 HTTPS 服务的证书验证。
- 新建独立协议适配层，复用现有传输工作任务、介质独占、资源校验与安装恢复；网页与LocalSend不能同时抢占文件消费者。同名文件初期拒绝覆盖，后续覆盖仍需现有身份核对与明确确认。
- 官方上传是整文件请求，sha256允许缺省；现有网页API仍以已知摘要和64KiB块为前提。整文件接收基础层复用已有暂存/分块和安装事务，由owner在收完后计算摘要；不需要第二份整文件临时文件。提供摘要时核对，未提供时计算内容身份。协议层不能自行写最终文件，须接入同一配额、取消和掉电恢复。
- LocalSend不能宣称支持现有网页的跨重启64KiB续传。客户端中断后采用重发，未安装的暂存文件不可出现在书架中；取消、断连、拔卡、睡眠、离页均需收敛所有权。

## 验收

先通过主机协议测试：发现、自发现过滤、PIN/确认、令牌与地址隔离、非法路径、超限、缺省摘要、摘要不符、截断、并发、取消和安装恢复。再用官方桌面客户端实传《绍宋》与霞鹜文楷，核对完整SHA；最后验证Android/iOS、路由器组播、热点、设备内存峰值、吞吐与停止恢复。软件替身不能代替这些互通结果。
