# 同源串行传输服务

`pn_transfer_service` 把原生上传事务与文件port装配成网络无关的串行owner。PC HTTP的 `pn_transfer_host` 已使用这层服务，不再自行管理会话或查询书库文件。服务同源编入ESP-IDF；设备HTTP队列、WiFi及传输页尚待接通。

## 资源与调用

open借用已有pool、media与平台ctx，复制可信固定根和默认选项，不取得WRITE、不写文件。选项不能预置覆盖授权；授权属于每次BEGIN命令。对象、pool、media及平台ctx活动期间不能移动。设备使用 [FAT适配](DEVICE_TRANSFER_STORAGE.md) 生成的默认选项，必须借用阅读/字体/USB共用的介质服务。

execute只由一个owner同步调用，命令结构拥有名称/身份等小数据，CHUNK借用最多64KiB只读数据。网络层必须先完成认证及长度检查，再把请求交给owner；本次execute完成后可释放该请求数据。若网络层使用队列，仍在排队/执行的请求必须保持有效，停止入口须先阻止新请求、等待已接收命令完成，再串行STOP并确认回执。服务本身不管理队列，不创建线程、不提供授权，也不让HTTP线程并发调用介质服务。

| 操作 | 契约 |
| --- | --- |
| BEGIN | 先验证请求，再关闭活动上传；新请求单独携带明确旧身份覆盖许可 |
| OPEN | 强制关闭重开，验证并重新同步持久记录后返回确认位置 |
| CHUNK | 同ID复用活动会话；切ID或不确定状态先恢复；只有持久成功才返回快照 |
| COMPLETE | 完整摘要/格式校验及恢复式安装，返回持久阶段和清理提示 |
| CANCEL | 共享事务的持久取消；不删除已安装资源 |
| FILE | 关闭活动上传，临时READ租约查询固定类别目录的精确长度与完整摘要 |
| STOP | 关闭活动句柄/租约并永久停止本服务实例，保留持久续传文件 |

STOP可重复，介质失效时仍允许STOP/close释放旧租约。STOP后其他命令返回CANCELLED；重新开启必须close后open。服务捕获介质代次，失效或换代拒绝操作；换代后平台ctx也必须按新挂载重新配置，不能只重开服务复用旧ctx。

错误不修改reply；传输层不能把上一次reply序列化成当前请求的成功ACK。BEGIN/FILE的名称错误和零ID在切会话前拒绝。合规的新ID切换会保留前一个上传的持久状态，但不保留它的活动租约；之后按原ID恢复。CHUNK同步失败后的自动恢复仍需再次获得正向同步成功，不能以日志读回代替落盘确认。

FILE查询只接受类别及basename，按固定根拼接路径，拒绝未知类别、路径名、非常规文件与主机符号链接；检查所有父目录。查询后释放READ，不阻止下一次上传。上层仍须在明确覆盖请求中携带查询到的旧长度和摘要；安装port再次核对，不能把查询当成覆盖许可。

## 验证

`python tools/dev.py host` 的transfer_service使用真实文件验证READ冲突、两个会话切换、暂停/停止/重新打开后续传、完整安装、旧文件身份查询、链接拒绝、错误输出保持、坏块摘要、日志已写但同步返回失败后的重新确认，以及持有WRITE时失效仍可停止并释放。transfer_http继续通过真实TCP验证改装后的PC入口、认证、重启、覆盖和书籍/字体/图片安装。

底层事务和文件安装契约见 [上传事务](UPLOAD_TRANSACTION.md) 与 [文件安装](UPLOAD_FILES.md)。共享服务和PC测试不证明设备HTTP、无线、功耗或FAT掉电可靠性。
